# Create Handoff

このセッションの作業を別セッションのエージェントに引き継ぐためのハンドオフドキュメントを作成する。
徹底的かつ**簡潔**なドキュメントを目指す。重要な詳細を失わずにコンテキストを要約・圧縮することがゴール。

## プロセス

### 1. メタデータの収集
以下のコマンドでメタデータを取得する:
- `git rev-parse --short HEAD` — 現在のコミットハッシュ
- `git branch --show-current` — 現在のブランチ名
- `date '+%Y-%m-%d %H:%M:%S %z'` — 現在の日時

### 2. ファイルパスの決定
以下の規則でファイルを作成する:
- パス: `thoughts/handoffs/ENG-XXXX/YYYY-MM-DD_HH-MM-SS_ENG-XXXX_description.md`
  - `YYYY-MM-DD` は今日の日付
  - `HH-MM-SS` は現在時刻（24時間形式）
  - `ENG-XXXX`の`XXXX` はチケット番号
  - `description` は作業内容の簡潔なkebab-case説明
- チケットありの例: `thoughts/handoffs/ENG-2166/2025-01-08_13-44-55_ENG-2166_create-context-compaction.md`
- チケットなしの例: `thoughts/handoffs/2025-01-08_13-44-55_create-context-compaction.md`

### 3. ドキュメントの作成
以下のテンプレートに従って記述する:

```markdown
---
date: [ISO形式の現在日時（タイムゾーン付き）]
git_commit: [現在のコミットハッシュ]
branch: [現在のブランチ名]
status: complete
---

# Handoff: {簡潔な作業説明}

## タスク
{取り組んでいたタスクの説明と各タスクのステータス（完了/作業中/計画済み）。
実装計画に基づいて作業している場合は、どのフェーズにいるかを明記する。
セッション開始時に提供された計画書や調査ドキュメントがあれば参照する。}

## 重要な参照資料
{従うべき重要な仕様書、アーキテクチャ決定、設計ドキュメントを記載する。
最も重要な2-3件のファイルパスのみ。該当なしの場合は空欄。}

## 最近の変更
{コードベースに加えた変更を `ファイルパス:行番号` 形式で記述する}

## 学んだこと
{重要な発見 — パターン、バグの根本原因、作業を引き継ぐ人が知るべき情報。
具体的なファイルパスを含めること。}

## 成果物
{作成・更新した成果物のファイルパスや `file:line` 参照の網羅的なリスト。
機能ドキュメント、実装計画など、作業再開時に読むべきもの。}

## 次のステップ
{次のエージェントが達成すべきアクションアイテムと次のステップのリスト}

## その他のメモ
{上記カテゴリに収まらないが引き継ぎに有用な情報。
コードベースの関連箇所、関連ドキュメントの場所など。}
```

### 4. 完了後の応答
ドキュメント作成後、ユーザーに以下の形式で応答する:

```
ハンドオフを作成しました！新しいセッションで以下のコマンドで作業を再開できます:

/resume-handoff thoughts/handoffs/2166/2025-01-08_13-44-55_2166_create-context-compaction.md
```

## ルール
- **情報は多めに、少なくしない**。このテンプレートは最低限の定義であり、必要に応じて情報を追加する
- **徹底的かつ正確に**。上位の目標と下位の詳細の両方を含める
- **過度なコードスニペットを避ける**。重要な変更の簡潔なスニペットは良いが、大きなコードブロックやdiffは含めない。`path/to/file.ext:line` 形式の参照を優先する
