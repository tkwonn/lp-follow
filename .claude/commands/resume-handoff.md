# Resume work from a handoff document

ハンドオフドキュメントから作業を再開するためのインタラクティブなプロセス。
前回のセッションで得られたコンテキスト、学び、次のステップを理解して作業を継続する。

## 初期応答

このコマンドが呼び出されたとき:

1. **ハンドオフドキュメントのパスが指定された場合**:
   - ハンドオフドキュメントを完全に読み込む
   - リンクされている計画書や調査ドキュメント（`thoughts/plans` や `thoughts/research` 配下）があれば直接読み込む（サブエージェントは使わない）
   - ハンドオフドキュメントで言及されている追加ファイルを読み込み、関連コンテキストを収集する
   - アクションの方針をユーザーに提案し、確認を得るか、方向性について質問する

2. **チケット番号（ENG-XXXXのような）が指定された場合**:
   - `thoughts/handoffs/ENG-XXXX/` ディレクトリの内容を一覧表示する
   - **ファイルが存在しない場合**: 「ハンドオフドキュメントが見つかりません。パスを指定してください」と伝える
   - **ファイルが1つの場合**: そのハンドオフを使用する
   - **ファイルが複数の場合**: ファイル名の日時（`YYYY-MM-DD_HH-MM-SS` 形式）から最新のハンドオフドキュメントを使用する
   - ハンドオフドキュメントを完全に読み込む
   - リンクされている計画書や調査ドキュメントがあれば直接読み込む
   - アクションの方針をユーザーに提案し、確認を得る

3. **パラメータなしの場合**:
   ```
   ハンドオフドキュメントから作業を再開します。利用可能なハンドオフを探します。

   どのハンドオフから再開しますか？

   ヒント: パスを直接指定することもできます:
   /resume-handoff thoughts/handoffs/ENG-XXXX/YYYY-MM-DD_HH-MM-SS_ENG-XXXX_description.md

   またはチケット番号で最新のハンドオフを指定できます:
   /resume-handoff ENG-XXXX
   ```
   ユーザーの入力を待つ。

## プロセス

### ステップ 1: ハンドオフの読み込みと分析

1. **ハンドオフドキュメントを完全に読み込む**:
   - Read ツールを limit/offset パラメータなしで使用する
   - すべてのセクションを抽出する:
     - タスクとそのステータス
     - 最近の変更
     - 学んだこと
     - 成果物
     - 次のステップ
     - その他のメモ

2. **関連ファイルの調査タスクを並列で起動する**:
   ハンドオフの内容に基づいて、現在の状態を検証するリサーチタスクを並列で実行する:
   - 成果物セクションに記載されたドキュメントを読み込む
   - 参照されている実装計画を読み込む
   - 言及されている調査ドキュメントを読み込む
   - 主要な要件と決定事項を抽出する

3. **すべてのタスクが完了するまで待つ**

4. **特定された重要なファイルを読み込む**:
   - 「学んだこと」セクションのファイルを完全に読み込む
   - 「最近の変更」のファイルを読んで変更内容を把握する
   - 調査中に発見された新しい関連ファイルを読み込む

### ステップ 2: 分析結果の提示

以下の形式で包括的な分析を提示する:

```
[日付] のハンドオフを分析しました。現在の状況:

**タスク:**
- [タスク1]: [ハンドオフ時のステータス] → [現在の検証結果]
- [タスク2]: [ハンドオフ時のステータス] → [現在の検証結果]

**学びの検証:**
- [file:line 参照付きの学び] - [有効/変更あり]
- [発見されたパターン] - [適用可能/変更あり]

**最近の変更の状態:**
- [変更1] - [確認済み/欠落/変更あり]
- [変更2] - [確認済み/欠落/変更あり]

**確認した成果物:**
- [ドキュメント1]: [要点]
- [ドキュメント2]: [要点]

**推奨する次のアクション:**
ハンドオフのアクションアイテムと現在の状態に基づいて:
1. [ハンドオフに基づく最も論理的な次のステップ]
2. [次の優先アクション]
3. [追加で発見されたタスク]

**発見された潜在的な問題:**
- [コンフリクトやリグレッション]
- [欠落している依存関係やコードの問題]

[推奨アクション1] から進めますか？それともアプローチを調整しますか？
```

ユーザーの確認を得てから進める。

### ステップ 3: アクションプランの作成

1. **TodoWrite でタスクリストを作成する**:
   - ハンドオフのアクションアイテムをTodoに変換する
   - 分析中に発見された新しいタスクを追加する
   - 依存関係とハンドオフのガイダンスに基づいて優先順位付けする

2. **プランを提示する**:
   ```
   ハンドオフと現在の分析に基づいてタスクリストを作成しました:

   [Todoリストを表示]

   最初のタスク [タスク説明] から開始しますか？
   ```

### ステップ 4: 実装の開始

1. 承認された最初のタスクから開始する
2. 実装全体を通じてハンドオフの学びを参照する
3. ドキュメントに記載されたパターンとアプローチを適用する
4. タスク完了に伴い進捗を更新する

## ガイドライン

1. **分析は徹底的に**:
   - ハンドオフドキュメント全体を最初に読む
   - 言及されたすべての変更がまだ存在するか検証する
   - リグレッションやコンフリクトがないか確認する
   - 参照されたすべての成果物を読む

2. **インタラクティブに進める**:
   - 作業開始前に発見事項を提示する
   - アプローチについて合意を得る
   - 軌道修正を可能にする
   - ハンドオフ時と現在の状態の差異に対応する

3. **ハンドオフの知見を活用する**:
   - 「学んだこと」セクションに特に注意を払う
   - 記載されたパターンとアプローチを適用する
   - 記載されたミスの繰り返しを避ける
   - 発見された解決策を基に構築する

4. **実行前に検証する**:
   - ハンドオフの状態が現在の状態と一致すると決めつけない
   - すべてのファイル参照がまだ存在するか確認する
   - ハンドオフ以降の破壊的変更がないか確認する
   - パターンがまだ有効か確認する

## よくあるシナリオ

### シナリオ 1: クリーンな継続
- ハンドオフのすべての変更が存在する
- コンフリクトやリグレッションなし
- アクションアイテムに明確な次のステップがある
- 推奨アクションに従って進める

### シナリオ 2: コードベースが分岐している
- 一部の変更が欠落または変更されている
- ハンドオフ以降に新しい関連コードが追加されている
- 差異を調整する必要がある
- 現在の状態に基づいてプランを適応させる

### シナリオ 3: ハンドオフの作業が未完了
- ハンドオフでタスクが「作業中」としてマークされている
- まず未完了の作業を完了する必要がある
- 部分的な実装を再理解する必要がある場合がある
- 新しい作業の前に完了に注力する

### シナリオ 4: 古いハンドオフ
- かなりの時間が経過している
- 大規模なリファクタリングが行われている
- 元のアプローチが適用できない可能性がある
- 戦略を再評価する必要がある

## インタラクション例

```
User: /resume-handoff thoughts/handoffs/ENG-2166/2025-01-08_13-44-55_ENG-2166_create-context-compaction.md
Assistant: ハンドオフドキュメントを読み込んで分析します...

[ハンドオフを完全に読み込む]
[リサーチタスクを起動]
[完了を待つ]
[特定されたファイルを読み込む]

[日付] のハンドオフを分析しました。現在の状況:

[分析結果を提示]

[推奨アクション1] の修正から進めますか？それともアプローチを調整しますか？

User: はい、進めてください
Assistant: [Todoリストを作成して実装を開始]
```
